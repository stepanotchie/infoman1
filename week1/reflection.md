Installing MySQL and making my own database (infoman1_2510) shows why databases are better than just using separate files, which is what Topic 1 is about. If a school kept student info in different spreadsheets in different offices, each office would have its own copy, and nothing would make sure those copies match. So if a student changes their address, one office might update it while the others don't. With MySQL, all the data is stored in one place instead of being copied everywhere, so this kind of mismatch is a lot less likely to happen.

Once this database is actually used for real student data, the DBA job that matters most right away is security and access control. Right now I'm just using the root account, which is fine because it's only me. But if real student records were involved, giving everyone that same full access would be risky, since Topic 2 explains how too much access can turn a small mistake into a big problem. Before anyone worries about backups or performance, someone needs to decide who is allowed to see or change what.
